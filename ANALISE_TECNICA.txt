## 1. PROBLEMAS CRÍTICOS IMEDIATOS

### 1.1 Requirements.txt Mal Formatado
**Localização:** geomoz-explorer/requirements.txt (linhas 7, 9)
**Problema:** Linhas concatenadas sem quebras de linha
```python
numpy>=1.26.0matplotlib>=3.10.9  # ← erro: duas linhas juntas
streamlit>=1.57.0streamlit-folium>=0.27.2earthengine-api>=1.7.0  # ← erro
```
**Impacto:** Falha na instalação de dependências
**Solução:** Separar as linhas corretamente


### 1.2 CORS Inseguro para Produção
**Localização:** api.py (linhas 18-23)
**Problema:** `allow_origins=["*"]` permite qualquer origem
**Impacto:** Vulnerabilidade de segurança em produção
**Solução:** Configurar origens específicas ou usar variável de ambiente


### 1.3 Debug Prints em Produção
**Localização:** gee_module.py (linhas 52, 66, 76, 82)
**Problema:** Prints de debug expõem informações sensíveis
```python
print(f"[DEBUG] Private key info: len={len(pk)}, starts_with={repr(pk[:50])}")
```
**Impacto:** Exposição de credenciais em logs
**Solução:** Usar logging estruturado com níveis apropriados


### 1.4 ThreadPoolExecutor Ineficiente
**Localização:** api.py (múltiplos endpoints)
**Problema:** Novo executor criado em cada request
```python
executor = ThreadPoolExecutor(max_workers=4)  # ← criado a cada request
```
**Impacto:** Sobrecarga de recursos, não reutiliza threads
**Solução:** Usar executor global ou async/await nativo


## 2. PROBLEMAS DE MANUSEIO DE ERROS

### 2.1 Exceções Genéricas
**Problema:** Muitos `except Exception` sem especificar tipo
**Exemplos:**
- api.py: linhas 201, 218, 244, 254, 280, 289
- gee_module.py: linhas 51, 81, 92, 120, 647, 655, 668, 909, 1198

**Impacto:** Dificulta debugging, esconde erros específicos
**Solução:** Capturar exceções específicas (ValueError, KeyError, etc.)


### 2.2 Silent Failures
**Problema:** Erros silenciosos sem logging
```python
except Exception:
    pass  # ← erro ignorado silenciosamente
```
**Impacto:** Difícil identificar problemas em produção
**Solução:** Logar sempre, mesmo com fallback


### 2.3 Feedback de Erro ao Utilizador
**Problema:** Frontend não mostra erros de forma clara
**Localização:** Explorer.tsx, HidroGeoMoz.tsx
**Impacto:** Má experiência de utilizador
**Solução:** Implementar toast notifications com mensagens claras


## 3. PROBLEMAS DE PERFORMANCE

### 3.1 Cache LRU Limitado
**Localização:** api.py (linhas 27, 35, 43)
**Problema:** `maxsize=1` para datasets grandes
**Impacto:** Cache insuficiente para múltiplas províncias/districtos
**Solução:** Aumentar maxsize ou usar cache distribuído (Redis)


### 3.2 Simplificação Hardcoded
**Problema:** Tolerância de simplificação fixa (0.01, 0.005)
**Impacto:** Não se adapta ao nível de zoom do utilizador
**Solução:** Simplificação dinâmica baseada no zoom


### 3.3 Sem Compressão de Respostas
**Problema:** GeoJSON não comprimido
**Impacto:** Tráfego de rede desnecessário
**Solução:** Habilitar gzip no FastAPI


### 3.4 Carregamento Inicial Lento
**Problema:** 10-20s para carregar geologia completa
**Impacto:** Má primeira impressão
**Solução:** 
- Pré-carregar dados em background
- Implementar lazy loading
- Mostrar progresso ao utilizador


## 4. PROBLEMAS DE SEGURANÇA

### 4.1 Credenciais Expostas
**Localização:** .env.local
**Problema:** Chaves de serviço em plain text
**Impacto:** Risco de comprometimento se o repositório for público
**Solução:** 
- Usar secrets manager (AWS Secrets, HashiCorp Vault)
- Adicionar .env.local ao .gitignore (já está)


### 4.2 Sem Autenticação/Autorização
**Problema:** API totalmente aberta
**Impacto:** Qualquer pessoa pode aceder a todos os dados
**Solução:** Implementar JWT ou OAuth2


### 4.3 Sem Rate Limiting
**Problema:** Sem limitação de requests
**Impacto:** Vulnerável a DoS, abuso de API
**Solução:** Implementar rate limiting (slowapi, redis)


### 4.4 Input Validation Insuficiente
**Problema:** Validação mínima nos endpoints
**Impacto:** Vulnerável a injeção de dados maliciosos
**Solução:** Validar rigorosamente todos os inputs com Pydantic


### 4.5 Sem HTTPS Enforcement
**Problema:** Não força HTTPS
**Impacto:** Tráfego em claro
**Solução:** Configurar middleware para forçar HTTPS


## 5. PROBLEMAS DE ARQUITETURA

### 5.1 Backend Monolítico
**Problema:** Tudo num único serviço FastAPI
**Impacto:** Difícil escalar componentes individualmente
**Solução:** Separar em microserviços:
- Serviço de dados geomoz
- Serviço de GEE
- Serviço de autenticação


### 5.2 Sem Testes Automatizados
**Problema:** Zero testes unitários/integração
**Impacto:** Refatoração perigosa, bugs não detectados
**Solução:** Implementar:
- Testes unitários (pytest)
- Testes de integração (FastAPI TestClient)
- Testes E2E (Playwright)


### 5.3 Sem CI/CD
**Problema:** Sem pipeline automatizado
**Impacto:** Deploy manual, propenso a erros
**Solução:** Configurar GitHub Actions ou GitLab CI


### 5.4 Sem Monitoramento
**Problema:** Sem métricas, alertas, logging estruturado
**Impacto:** Difícil diagnosticar problemas em produção
**Solução:** Implementar:
- Prometheus + Grafana
- Structured logging (structlog)
- Error tracking (Sentry)


### 5.5 Sem Documentação de Código
**Problema:** Comentários mínimos, sem docstrings
**Impacto:** Difícil manutenção por outros developers
**Solução:** Adicionar docstrings completas, type hints
